# AI 學習系統（learn-system）設計文件

- 日期：2026-09-26
- 狀態：待實作

- Port：5990

## 1. 背景與目的

把「MIT 學霸 AI 學習法」系統化成一套**可套用到任何領域**的學習工具。方法論三步：

1. **建框架** — 問「這個領域專家共享的核心思維模型是什麼」
2. **探邊界** — 問「專家最激烈的爭議點與各方論據」
3. **測試閉環** — 出「能甄別真理解 vs 死記硬背」的題目，作答、追錯因、補漏

核心精神：AI 是「增加認知痛苦的陪練」，不是答案機。

第一個套用領域：Python。

## 2. 需求

### 2.1 學習目標（四者都要）

| 代號 | 目標 | 系統對應做法 |
|---|---|---|
| a | 能從零自己寫出工具 | 實作題，**真的執行測試驗證** |
| b | 能看懂並改動別人／AI 寫的程式碼 | 讀碼題：給有 bug 的程式，找問題並說明 |
| c | 補齊底層原理 | 預測題：預測輸出並解釋原因 |
| d | 能通過檢定／面試 | 模擬考題型 |

### 2.2 形態

網頁應用，**以「概念（知識點）」為中心**，不是聊天室。對話功能收斂成右側可收合的抽屜，只在追問錯因時使用。

### 2.3 語料庫：可選，非必經

原文要求「先喂 6 本教材」以防 AI 片面。本系統做成可選：

- **預設（`verify_sources = false`）**：Claude 直接憑自身知識生成智識地圖，不抓任何外部資料。
- **選用（`verify_sources = true`）**：Claude 查證來源，每個概念附出處連結。

理由：2026 年的模型對 Python 這類主流領域已足夠熟，「專家共享的思維模型」直接問就有高品質答案。語料庫真正不可取代的時機只有三個——冷門領域、需要引用出處、需要驗證 AI 有沒有胡說。把語料庫做成必經流程，會白白多出爬蟲＋向量索引一整塊工程。

### 2.4 通用性要求

任何提示詞不得寫死 Python。所有生成內容必須由「領域名稱 + 使用者勾選的目標」驅動。

### 2.5 自動執行驗證：領域層級開關

只有「能寫」目標且在**可執行程式碼驗證的領域**（Python、JS…）才啟用真實執行驗證。經濟學、歷史這類領域做不到，一律由 Claude 批改。

判斷方式：生成智識地圖時，Claude 一併判斷該領域可否執行驗證，寫入 `domains.executable`。使用者可在領域設定中手動覆寫。

## 3. 系統架構

```
┌──────────────┐        ┌───────────────┐        ┌──────────────────────────┐
│  瀏覽器       │  HTTP  │  Flask :5990  │        │  Claude Agent SDK        │
│  HTML/JS     │ ←────→ │               │ ←────→ │  (claude_agent_sdk.query)│
└──────────────┘        │  SQLite       │        └────────┬─────────────────┘
                        └───────────────┘                 │ 需要時才用
                                                          ↓
                                              WebSearch / WebFetch（查證來源）
                                              subprocess（執行學習者程式碼）
```

- **Flask**：唯一服務，同時提供頁面與 JSON API
- **SQLite**：所有狀態（領域、概念、題目、作答、對話 session）
- **Claude Agent SDK**：所有需要「腦」的工作。沿用 command-center（5950）既有的 `claude_agent_sdk.query()` 呼叫方式與權限控制模式
- **背景任務**：生成智識地圖是長任務（1–2 分鐘），用背景執行緒執行，狀態寫入 DB，前端輪詢進度

### 3.1 Agent 呼叫的權限邊界

沿用 command-center 的白名單思路，針對本系統調整：

- 生成地圖／出題／批改：**唯讀**工具（`Read`、`WebSearch`、`WebFetch`、`Grep`）；`verify_sources=false` 時連網路工具都關閉
- 執行學習者程式碼：不經 Agent，由 Flask 自己的執行器處理（見 §9），避免把任意程式碼交給 Agent 執行

## 5. 網頁設計

只有兩個頁面。

### 5.1 首頁 — 領域清單

卡片式清單，每張顯示：領域名稱、掌握度百分比、概念總數、上次學習時間。右上角「＋ 新領域」。

### 5.2 建立新領域（一次性流程）

1. 輸入名稱
2. 勾選目標：能寫／能讀懂改／懂原理／能檢定（可多選）
3. 勾「需要查證來源」（預設**不勾**）
4. 按建立 → Claude 跑三問、生成智識地圖（1–2 分鐘，顯示進度）→ 完成後自動進入領域頁

生成失敗時顯示錯誤與重試鈕，可續傳不從頭。

### 5.3 領域頁

```
┌──────────────────────────────────────────────────────┐
│ Python        目標 能寫/讀碼/原理/檢定      掌握度 42% │
├──────────────────────┬───────────────────────────────┤
│ 智識地圖              │  概念：閉包                    │
│ ──────────            │  ┌─────────────────────────┐  │
│ ● 共識 5              │  │ 說明 + 例子（按需生成）   │  │
│   ○ 可變 vs 不可變     │  └─────────────────────────┘  │
│   ◐ 閉包   ← 你正在這  │  ┌─────────────────────────┐  │
│   ○ GIL               │  │ 題目                      │  │
│ ● 分歧 3              │  │ 你的作答（程式碼編輯器）   │  │
│   ○ ...               │  └─────────────────────────┘  │
│ ● 探索區              │  [出題]   [送出]               │
│   ○ ...               │  ───────────────────────────   │
│                       │  批改：錯在 late binding…      │
│                       │  ↳ 追問（對話抽屜在此展開）     │
├──────────────────────┴───────────────────────────────┤
│ 進度：掌握度熱圖 ／ 錯題本                             │
└──────────────────────────────────────────────────────┘
```

- **左欄**：智識地圖。三個分區，每個概念帶狀態燈（○ 未練／◐ 練習中／● 已掌握）。點擊切換右欄內容。
- **右欄**：選中概念的工作區。由上而下是「概念說明 → 出題 → 作答 → 批改」。
- **對話抽屜**：從右緣滑出、可收合。開啟時保持該領域的 Agent session（`domains.chat_session_id`），所以它記得你們剛才在練什麼。
- **底欄**：掌握度熱圖（概念 × 狀態）與錯題本（所有 `wrong`/`partial` 的作答，依概念分組）。

「教材」在本系統中不是一份固定講義，而是**點開概念時按需生成的說明＋例子**，需要查證時附官方文件連結。

## 6. 學習迴圈

1. 進入領域頁 → 系統推薦「下一個該練的概念」（優先序：`practicing` 且最近答錯 > `untested` > 其他），也可自行點選
2. 右欄生成該概念說明（首次生成後快取，之後秒開）
3. 按「出題」→ Claude 依概念 + 目標出題（約 3–10 秒）
4. 作答
5. 送出 → 批改
6. 答錯 → 對話抽屜可展開追問「為什麼」「再考我一題類似的」
7. 掌握度更新

## 7. 題型與批改

| 目標 | 出的題 | 批改方式 |
|---|---|---|
| 能寫 (`write`) | 給規格，寫出函式 | **執行學習者的程式對測試**，客觀判定 |
| 能讀懂改 (`read`) | 給一段有 bug 的程式，找出問題並說明 | **實際執行原版確認它真的會錯、修正版確認真的能修** + Claude 判斷說明是否到位 |
| 懂原理 (`principle`) | 預測程式輸出並解釋為什麼 | **實際執行取得真實輸出**比對學習者的預測 + Claude 檢查解釋是否切中要點 |
| 能檢定 (`exam`) | 模擬考題型 | Claude 批改 |

三種程式相關題型都有客觀錨點，不靠 AI 說了算，這是本系統相對於純聊天式學習的最大優勢。

`read` 題型要求出題時一併產出 `fixed_code`，用途是**驗證題目本身有效**：出題後系統先跑一次，確認原版真的失敗、修正版真的通過。若兩者行為一致，代表 AI 幻想了一個不存在的 bug，該題作廢重出。同理，`principle` 題的真實輸出由執行取得，不由 AI 聲稱。

當 `domains.executable = 0` 時（非程式領域），上述執行驗證全部停用，四種題型一律由 Claude 批改。

## 8. 掌握度計算

每個概念三種狀態：`untested`（未練）／`practicing`（練習中）／`mastered`（已掌握）。

規則：

狀態由**最近 5 次作答**即時重算（每次作答後重算一次，不累積歷史旗標）：

| 條件 | 狀態 |
|---|---|
| 從未作答 | `untested` |
| 最近 5 次中 ≥4 次 `correct` | `mastered` |
| 其餘（次數不足 5 次，或最近 5 次中 ≥2 次非 `correct`） | `practicing` |

`partial` 不計入 `correct`：部分正確仍代表有漏洞。

因為狀態是「最近 5 次」的滑動窗口，已達 `mastered` 的概念若之後答錯，舊的答對紀錄會被擠出窗口，狀態自動退回 `practicing`——不需要額外的「退回」規則。作答次數未滿 5 次時不會進入 `mastered`（樣本不足）。

採嚴格門檻（5 取 4）而非寬鬆版本，因為「以為自己會了」正是這套方法最想消滅的東西。

**範圍外**：不做間隔重複排程。之後若真的需要再加。

## 9. 安全與錯誤處理

### 執行學習者的程式碼

- 在獨立的暫存資料夾執行，**逾時 5 秒即終止**（防無窮迴圈）
- 執行完畢立即清除暫存檔
- 逾時或非預期錯誤 → 回報「執行逾時」或錯誤訊息，**不計入對錯**（避免因環境問題誤判學習者）

### Agent 呼叫失敗

- 逾時或失敗 → 前端顯示錯誤與重試鈕
- **已生成的內容不得遺失**（說明、題目一旦生成即入庫）

### 地圖生成中斷

- 狀態記錄在 `domains.status`，中斷後可續傳

### 密鑰

- 不得硬編碼任何 token。需要時讀 `~/CCProject/.secrets/`

## 10. 測試策略

- **框架**：pytest
- **Claude 呼叫在測試中以假回應取代**（真呼叫既花錢又不穩定）
- 必測項目：
  - 資料層 CRUD 與掌握度計算（含邊界：4/5 vs 3/5）
  - API 端點：建立領域、取概念、出題、作答、進度
  - 程式碼執行器：正常通過、測試失敗、逾時、語法錯誤
  - 地圖生成中斷後的續傳
