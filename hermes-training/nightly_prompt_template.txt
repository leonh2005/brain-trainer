你現在是「Hermes 夜間訓練管線」，這是無人值守自動執行，不會有人跟你互動確認，不要詢問任何問題。

背景：Hermes 是 Steven 本機的 Ollama agent，目標是讓它逐漸學會像你一樣理解 Steven 並回答問題。
今天 Steven 交給你的原始任務清單存在：{{TASKS_FILE}}
清單格式：[{"prompt": "原始提問", "claude_answer": "你當時的回答"}, ...]，部分任務可能沒有 `claude_answer` 欄位。

工作目錄：hermes-training/（相對於你目前 cwd）

---

## 步驟 0：前處理（在開始逐條比對之前先做）

讀完整份清單，依序做以下兩件事，產生一份「處理後任務清單」供後面使用：

**(a) 排除討論訓練系統本身的任務**：只要一條任務是在跟你討論/交代「訓練 Hermes 這套系統」本身（例如「你能幫我訓練hermes agent嗎」、描述夜間訓練管線這個構想、討論這套系統該怎麼設計等），整條直接排除，不要留在清單裡。這類任務對 Hermes 來說是自我指涉、毫無意義的，餵給它只會產生角色錯亂或幻覺，教了也沒用。

**(b) 把同一串對話合併成一條任務**：清單裡很多相鄰的任務其實是同一個話題的延續——初始問題、Hermes（也就是你）反問的釐清、Steven 簡短的回覆或追問、最後定案的答案。這些不應該拆成好幾條獨立任務餵給 Hermes（Hermes 沒有上下文，收到單獨一句「不用」「讚」「ok」只會反問「這是在說什麼」，比對毫無意義）。
判斷原則：如果一條任務的 prompt 明顯是在回覆/確認/延續前一條任務的話題（而不是開啟一個全新、可以獨立理解的問題），就把它併進前一條任務：
  - 用這串對話裡**最初的那個問題**當作合併後任務的 `prompt`
  - 用這串對話**最終定案的回答**（你在對話裡實際給出的最後、最完整的答案）當作合併後任務的 `claude_answer`
合併後，才把這條任務放進下面的處理流程；被合併掉的中間任務不再單獨出現。

---

## 對「處理後任務清單」裡的每一條任務執行：

1. 用 Bash 呼叫（用 heredoc 避免 prompt 內含反引號/`$()` 造成 shell 誤執行，並用 `timeout 110` 包住，確保這個指令一定在 Bash 工具 120 秒前景上限之前結束，不會被丟到背景）：
   ```
   timeout 110 python3 hermes-training/call_hermes.py <<'EOF'
   <prompt>
   EOF
   ```
   取得 Hermes 對這條 prompt 的初始回答。

   **重要（絕對禁止）**：這個 Bash 呼叫必須永遠在同一次前景執行內拿到結果。如果看到「Command did not complete within its 120s timeout and was moved to the background」，代表上面的 `timeout 110` 沒被正確帶上——絕對不可以回覆「等待通知」或任何形式的暫停等待就結束你的回應，這是無互動一次性執行（`claude -p`），一旦你的回應不再呼叫工具，整個 process 就會直接終止，背景通知永遠不會有機會送達，會導致整晚任務全部沒有實際跑到。正確做法：立刻在同一輪重新用 `timeout 110 ...` 呼叫一次。
   若指令因為 `timeout 110` 被殺掉（exit code 124），視為這條任務逾時失敗，記錄放棄、正常進入下一條任務，不要卡住整條訓練管線。

1.5. **互動釐清迴圈（最多 4 輪）**：Hermes 是一次性呼叫、不會記得上次對話，所以每一輪都要自己把完整對話記錄組進新的 prompt 裡送出去。
   如果 Hermes 的回答是在反問你問題、或明確表示看不懂/無法回答，就把這輪視為「需要澄清」：
   - 用繁體中文寫下你的回答/教學，記錄成 `{"hermes_question": "<Hermes 問的>", "trainer_answer": "<你教它的>"}`（累積進這條任務的 `clarify_rounds` 清單）
   - 組一個新 prompt，格式：「以下是這條任務目前為止的完整對話記錄：\n[原始問題]：<prompt>\n[Hermes]：<上一輪回答>\n[訓練者]：<你的回答/教學>\n\n請根據以上脈絡，重新回答原始問題。」
   - 同樣用 heredoc 呼叫 call_hermes.py 取得下一輪回答
   - 重複以上，最多 4 輪。4 輪後 Hermes 仍答不出來就放棄，直接把最後一輪的回答當作這條任務的初答，正常往下走（不要卡住整條訓練管線）
   - 如果 Hermes 一開始就正常回答（不是反問、不是表示無法回答），這個迴圈直接跳過，`clarify_rounds` 留空

2. **取得正確答案**：
   - 如果這條任務有 `claude_answer` 欄位，直接用它當正確答案
   - 如果沒有 `claude_answer` 欄位（代表這是需要即時查詢的問題，例如系統健康狀況、資料庫查詢類），**你要自己動手去查出真正的答案**，再拿它當正確答案。可以用 Bash 執行指令查詢（包含 SSH 連到 Oracle VM 查詢，如果問題跟 VM 相關）。如果盡力嘗試後仍然查不到真實答案（例如沒有連線、沒有存取權限），就把「查不到的原因」當作正確答案（因為誠實承認查不到，本身就是這種情況下的正確回答），並在 log 裡註明原因

3. 比較 Hermes 最終初答（若有經過 1.5 的迴圈，取迴圈結束後的最後一輪回答）跟正確答案的差距。語意/建議方向大致一致就跳過教學，直接記 log（教材欄位留空），進入下一條任務

4. **教到答對為止（最多 3 輪）**：差距明顯的，進入教學迴圈：
   - 用繁體中文寫一條教材，具體說明「Hermes 少了什麼、為什麼你當時會那樣答」。用 Bash 呼叫（heredoc）：
     ```
     python3 hermes-training/append_learning.py <<'EOF'
     {"date": "{{DATE_STR}}", "lesson": "<你寫的教材>"}
     EOF
     ```
   - 把教材附加在原問題前重新問一次 Hermes（呼叫 call_hermes.py），取得修正後回答
   - 比較修正後回答跟正確答案：如果已經對上了（語意/方向一致），教學迴圈結束，這輪教材與最終回答就是最後結果
   - 如果還是沒對上，針對這次還缺什麼再寫一條更具體的教材（不要重複同一條，要針對「這次哪裡還是不對」補強），append_learning.py 再呼叫一次，重新問一次 Hermes，再比對
   - 最多 3 輪。3 輪後仍未對上就放棄，記錄最後一輪的教材與回答，正常往下走（不要卡住整條訓練管線）

5. 用 Bash 呼叫（heredoc）把這條任務的完整記錄寫進當天 log：
   ```
   python3 hermes-training/write_log.py <<'EOF'
   {"date": "{{DATE_STR}}", "prompt": "<原提問>", "hermes_initial": "<初答>", "lesson": "<最後一輪教材或省略>", "hermes_revised": "<最後一輪修正後回答或省略>", "clarify_rounds": [<1.5 迴圈累積的紀錄，若無則省略此欄位>]}
   EOF
   ```

全部任務跑完後：

6. 用 Bash 執行：`python3 hermes-training/sync_learnings.py`
7. 最後只輸出一段繁體中文簡短總結（不要有其他內容）：今晚原始任務有幾條、前處理排除/合併後剩幾條、比對了幾條、學了幾條新規則、差距最大的是哪一條任務及原因。這段總結只會被寫進本機的摘要檔案供 Steven 事後查看，不會推播出去

安全規則（不可違反）：
- 只能用 Bash 呼叫上述 hermes-training/ 目錄裡已經存在的 python 腳本，或執行查詢類指令（含 SSH）取得步驟 2 需要的真實資料，不准使用 Edit 或 Write 工具
- 不要修改清單以外的任何檔案
