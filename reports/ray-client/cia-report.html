Ray 常駐服務：效能比較與 CIA

2026-11-23 · Mac（arm64）＋ Oracle A1（4 OCPU / 23GiB）

一、0050 回測效能比較

環境耗時checksum解讀
Mac 單process（Python 3.12.13）0.301s3194796836.33最快，不需搬資料
VM 單process（Python 3.12.3）0.883s3194796836.33比 Mac 慢約 3 倍
VM 4 worker 平行0.265s3194796836.33只比 Mac 快 12%，未算搬資料／Ray 成本

三者 checksum 完全相同，結果正確。**結論：這個 0050 回测不值得丟到 VM。** 判斷規則：可拆 ≥4、單次 >30 秒、資料搬運量小才考慮遠端；其餘留本機。

二、CIA 三方落實

C · Confidentiality（機密性）

  • SSH 金鑰登入（~/.ssh/oracle_line_bot），禁止密碼。
  • Mac tunnel 只監聽 127.0.0.1:10001；Ray 無驗證機制，絕不開公網。
  • VM iptables 持久化規則只放行 22，其餘 REJECT；實測 10001 公網不可達。
  • 金鑰放 ~/.secrets/，不進 public repo；發布腳本會擋疑似金鑰／OCID。

I · Integrity（完整性）

  • 兩端 Ray 版本固定在 2.40.0，pool.connect() 啟動時檢查版本。
  • 每次提交記錄 code_sha12（原始碼 hash），可追是哪一版程式跑的。
  • 回測比對用 checksum；三邊數字一致才採信。
  • HTML 報告發布前掃描敏感字串，commit 前後可追。

A · Availability（可用性）

  • VM：ray-head.service，systemd Restart=always + linger。
  • Mac：com.steven.ray-tunnel LaunchAgent，KeepAlive=true + ServerAliveInterval。
  • 健康檢查：./health.sh（自動用 venv）→ OK ray_cluster CPU=4.0。
  • 使用 log：logs/ray_usage.log；usage.py 7 顯示每日次數、任務數、秒數、錯誤與「是否值得保留」判讀。

三、目前 observable 狀態

  • launchctl list | grep ray-tunnel → 有 pid， KeepAlive 生效。
  • systemctl --user is-active ray-head.service → active。
  • usage.py 7 → 1 次、16 任務、0.6 秒、0 錯誤；判讀為低使用量，建議按需啟用而非常駐。

你要求改常駐，因此服務維持常駐；但 log 的判讀會如實指出低使用量，日後可依數據決定是否關掉。
