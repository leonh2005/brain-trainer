Python ＋ SQL：十個有趣又實用的專案

2026-11-23 · 每個都按 PRD / SOW 四核心區塊寫：Goal / Scope / Who / When-Risk · 數字為示例，可依實際調整

這份報告同時是 Ray 常駐服務的測試任務之一：提交紀錄已寫入 logs/ray_usage.log，可用 python3 usage.py 7 查使用率。以下是十個「一個人就能做、Python 寫邏輯、SQL 管狀態」的點子，刻意避開空泛的 AI 口號，每個都有可驗收的成果。

1. 個人知識庫語意搜尋

SQLite FTS5PythonEmbedding

Why · 背景與目標

  • 痛點：Obsidian vault 越長越大，關鍵字搜尋找不到「意思相近」的舊筆記。
  • SMART：4 週內建立索引，對 5,000 篇筆記的queries 平均回應 < 1 秒。
KPI：搜尋命中率 ≥ 80%、索引更新 < 5 分鐘

What · 範疇與交付

  • In：Markdown 解析、FTS5 索引、embeddings 向量表、CLI 搜尋。
  • Out：不改動原筆記、不做網頁版。
  • 交付：indexer.py、search.py、SQLite schema、使用說明。

Who · 利害關係人

  • Sponsor / 使用者：你自己。PM：你（兼任）。
  • RACI：你 R/A；Obsidian 為 Consulted；無需知會其他人;
  • 受眾：未來的自己。

When & Risk

  • 里程碑：W1 schema、W2 索引、W3 搜尋、W4 驗收。
  • 資源：本機 + 幾小時；無預算。
  • 風險：embedding 模型更換導致索引不相容 → 版本號寫進 DB，必要時重建。

2. 台股事件驅動回測平台

SQLitePythonBacktest

Why

  • 痛點：每次回测都重寫程式，參數與結果散在 /tmp。
  • SMART：6 週內把 0050/0052 的回测結果結構化，任何參數组合可重現。
KPI：每筆結果含程式 hash + 資料版本，100% 可重跑

What

  • In：K線入庫、策略參數表、回测結果表、_report_ 產出。
  • Out：不下單、不做即時交易。
  • 交付：schema.sql、run.py、report.html。

Who

  • Sponsor/PM/執行：你；顧問：過去的回測筆記。
  • 受眾：你自己的投資決策。

When & Risk

  • W1 資料、W2 schema、W3 策略、W4 報表、W5-6 驗證。
  • 預算：0；使用既有 Shioaji/FinMind。
  • 風險：資料分割/股息還原錯誤 → 寫 unit test 與 checksum，已有踩坑紀錄可复用。

共同pattern：這十個都適合的技術骨架

  • Python 做編排：抓取、清洗、計算、通知；保持純函式可測。
  • SQL 做事實來源：SQLite（單機）或 Postgres（多人）；所有状态可查、可回溯。
  • idempotency：用 source + external_id 當唯一鍵，重跑不重複。
  • 可觀測：每次執行寫 log（時間、筆數、耗時、錯誤），才能判斷是否值得保留 —— 正是我們剛為 Ray 做的
